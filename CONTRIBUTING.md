# Mitmachen

Danke, dass du Speicherwacht verbessern willst! Fehler und Ideen bitte als [Issue](https://github.com/speicherwacht/integration/issues/new/choose). Sicherheitslücken bitte vertraulich melden, siehe [SECURITY.md](SECURITY.md).

## Pull Requests

- Kleine Änderungen (Fehlerbehebungen, Übersetzungen, Doku) gern direkt als Pull Request. Neue Funktionen, Hersteller-Vorlagen oder Umbauten bitte erst in einem Issue besprechen, damit niemand umsonst arbeitet.
- **Basis ist `dev`**, nicht `main`. `main` enthält nur veröffentlichte Stände, an denen die HACS-Installationen hängen.
- Vor dem Pull Request: `uv run pytest`, `uv run ruff check .` und `uv run ruff format .`. Die Home-Assistant-Tests (`tests/ha/`) laufen nur in GitHub Actions, unter Windows nicht. Bei Pull Requests aus Forks startet die CI erst, wenn ich sie freigebe.
- Code, Kommentare und Entity-IDs auf Englisch. **UI-Texte nur über `tools/make_strings.py`** (`uv run python tools/make_strings.py .`), das `strings.json`, `translations/de.json` + `en.json` und `icons.json` erzeugt. Die JSON-Dateien bitte nicht direkt ändern.
- `CHANGELOG.md` und Versionsnummer bitte nicht ändern. Den Eintrag und das Release übernehme ich.

## KI-Assistenten

Beiträge mit Hilfe von KI-Assistenten (z. B. Claude Code) sind willkommen, wenn du die Änderung selbst verstanden und getestet hast. Bitte im Pull Request kurz erwähnen; ein `Co-Authored-By`-Trailer im Commit genügt.

[`CLAUDE.md`](CLAUDE.md) und [`docs/ENTWICKLUNG.md`](docs/ENTWICKLUNG.md) enthalten die Projektregeln, die dein Assistent lesen sollte. Release, Veröffentlichen und alles an `main` mache nur ich.

## Besonderheiten von Speicherwacht

- **Neue Hersteller-Vorlage nur mit Fixture** in `tests/fixtures/` (Herkunft in `_index.json`), am besten aus einer Diagnose-Datei. Nur aus dem Quellcode abgeleitete Vorlagen gelten als „experimentell“. Formate nie raten.
- **Fachwerte nur mit Quelle** (Definitionen, Schwellen), eingetragen in [`docs/ENTWICKLUNG.md`](docs/ENTWICKLUNG.md); eigene Annahmen als solche kennzeichnen.
- **Keine personenbezogenen Daten ins Repo:** keine eigenen Zählerstände, Verläufe oder Wirkungsgrade, auch nicht als Testwerte. Fixtures haben echtes Format und erfundene Werte; `tests/sim.py` simuliert einen Speicher.
- **Fehler in Quell-Integrationen** (z. B. Huawei Solar, solarman) bitte dort melden, nicht in Speicherwacht umgehen.

## English

Contributions are welcome. Small fixes, translations and docs can go straight to a pull request; for new features, manufacturer templates or larger changes please open an issue first. Target the **`dev`** branch, run `uv run pytest` and `uv run ruff check .` before opening the PR, and keep code and comments in English. UI texts are generated by `tools/make_strings.py`; please don't edit the JSON files directly. New templates need a fixture, technical values a source, and no personal meter data goes into the repo. AI-assisted contributions are fine if you have reviewed and tested them yourself; please mention it in the PR. Issues and pull requests in English are welcome.
